# 实验新手常见问题

本文整理实验中常见的操作问题，帮助刚接触 Linux 的同学逐步排查。各实验的编译和测试方式可能不同，请同时参考[对应实验的文档](../labs/index.md)。

## 修改源码后，编译或测试结果没有变化

编辑器里显示的新代码、磁盘上保存的源文件和编译生成的程序，可能处于不同的状态。遇到结果没有变化时，可以按下面的顺序检查。

### 1. 先保存文件

在 VS Code 中，修改代码后按 **Ctrl+S**，将当前文件的修改保存到磁盘。如果修改了多个文件，需要分别保存，或使用菜单中的“文件 → 全部保存”。

编辑器中尚未保存的修改通常只存在于编辑器的内存中。编译工具读取的是磁盘上的文件，并不能直接读取编辑器里未保存的内容。因此，即使屏幕上已经显示新代码，编译时也可能仍然使用旧代码。

### 2. 确认终端和编辑器使用的是同一个项目

在准备运行编译命令的终端中，逐行输入以下命令，每行输入后按回车：

```bash
pwd
ls
```

- `pwd` 显示终端当前所在目录的完整路径。
- `ls` 列出当前目录中非隐藏的文件和子目录，帮助你核对这里是否有实验的源文件、`Makefile` 等文件。

在 VS Code 中查看正在编辑的文件的完整路径（例如右键点击文件标签，选择“复制路径”），与 `pwd` 的结果对照，确认该文件属于终端中的这个实验项目。如果同一实验有多份副本，不能只看文件名是否相同，还要核对所在目录。使用 WSL 或远程连接时，也要确认编辑和编译发生在同一个环境中。

如果终端所在目录不对，可以用 `cd` 切换目录。例如：

```bash
cd /path/to/your-lab
```

`cd` 用于切换终端的当前目录。这里的 `/path/to/your-lab` 是占位路径，请替换为你实际的实验项目路径；路径中含空格时，用英文双引号包住整个路径。切换后再用 `pwd` 和 `ls` 核对，并按照实验文档要求在指定目录编译，通常是包含 `Makefile` 的项目根目录。

### 3. 理解 make 为什么没有重新编译

使用 `make` 的项目通常在 `Makefile` 中描述构建规则，包括要生成的“目标”、目标依赖哪些文件，以及如何生成它。目标可以是编译生成的程序，也可以是组织其他构建步骤的名称。

`make` 根据这些依赖关系和文件的修改时间，判断是否需要重新编译。对于普通文件目标，如果目标不存在，或者它依赖的源文件比它更新，通常就需要重新生成目标；如果相关文件没有变化，就可以跳过重复编译。

如果修改没有保存到磁盘，磁盘上的源文件内容和修改时间就不会因这次编辑而更新，`make` 也就可能认为无需重新编译。如果改的是另一份项目中的文件，当前项目同样不会因此重新编译。

有时终端会显示：

```text
make: Nothing to be done for 'all'.
```

这句话只表示：按照当前构建规则，`make` 判断当前的 `all` 目标无需重建。`all` 是项目中常见的目标名称，具体包含哪些构建步骤由该项目的 `Makefile` 决定。

**这不代表代码正确，也不代表测试通过；不能单凭这句话断定文件没有保存。** 文件已经保存并且之前已完成编译，也可能出现这条提示。应结合保存状态、文件路径和构建规则一起判断。

### 4. 保存后重新编译，再运行实验要求的测试

确认文件已保存、目录正确后，按照当前实验文档重新编译。如果实验要求使用 `make`，就在指定目录运行：

```bash
make
```

不指定目标时，`make` 会构建 `Makefile` 中的默认目标，许多项目将它设为 `all`。如果实验文档要求其他命令或目标，请以实验文档为准。

阅读编译输出：如果编译失败，先根据错误信息修改并保存，再重新编译。失败后可能仍留有旧程序，直接运行它不能验证本次修改。

编译成功后，再按照**各实验自己的要求**运行测试，并确认运行的是当前项目刚刚构建的程序。不同实验的测试命令、输入和结果含义可能不同，不要把某个实验的测试命令当成所有实验通用的步骤。编译成功也不等于测试通过。

### 5. 仍有问题时，再考虑是否需要清理构建产物

`make clean` 不是每次修改代码后的必需步骤。只有项目确实提供了 `clean` 目标，并且实验文档或排查情况表明需要清理旧的构建产物时，才考虑使用。

`make clean` 表示让 `make` 执行项目定义的 `clean` 目标，通常用于删除编译生成的文件，具体行为由 `Makefile` 决定。使用前先确认该目标的作用；清理后还需要按实验要求重新编译，再运行测试。

如果保存和目录均已确认，修改仍未触发预期的编译，可以进一步检查修改的文件是否属于当前目标的依赖，或向助教说明已尝试的步骤及相关编译、测试输出。
